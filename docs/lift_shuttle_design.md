# 리프트·셔틀 구조 검토와 기능 정의

작성: 2026-11-18 · 대상: Unity 6000.6.8f1, ML-Agents (Python 1.1.0 / Unity 패키지 3.0.x)

## 1. 구조 검토 결과

### 셔틀: 4방향 파렛트 셔틀
셔틀 한 대가 메인 통로(X 방향)와 레인(Y 방향)을 모두 주행해야 하므로 **4방향(4-way) 셔틀**로 정했습니다.

| 구성 | 내용 |
|---|---|
| 차체 | 0.96 × 0.96 m, 높이 0.18 m (레일 바닥 기준). 레인 레일의 파렛트 받침보다 낮아서 **빈 셔틀은 적치된 파렛트 아래를 지나갈 수 있음** |
| 바퀴 2세트 | `WheelsX`(메인 통로용), `WheelsY`(레인용). 교차점(Junction)에서만 바퀴 세트를 바꿔 방향 전환 |
| 잭(Jack) | 상판을 0.04 m 올려 파렛트를 레일에서 0.03 m 띄움. 짐을 든 셔틀은 적치 셀 아래를 지날 수 없음 |
| 센서 | 4방향 `Sensor_PX/NX/PY/NY` (Unity 레이캐스트 위치) |

검토한 다른 방식: 모셔틀(통로용) + 자셔틀(레인용) 조합은 셔틀이 직접 통로와 레인을 오가는 요구사항과 맞지 않아 제외했습니다.

### 레일: C형 단면
- 안쪽 아래 플랜지 = 바퀴 주행면, 바깥쪽 위 받침(Ledge) = 파렛트 양 끝을 받침
- 레인 레일은 받침이 있고, 메인 통로 레일은 받침이 없음(통로에는 보관하지 않음)

### 롤러 레일: 리프트와 셔틀의 공통 접점
P&D 스테이션(각 층의 입출고 전달 위치)과 리프트 캐리지는 **같은 롤러 레일 구조**입니다. 레일의 바퀴 주행면은 그대로 두고, 위쪽 받침 자리를 구동 롤러로 바꾼 형태입니다.

- **현재 방식:** 리프트 캐리지 롤러 → P&D 스테이션 롤러로 파렛트를 컨베잉하고, 셔틀이 P&D 아래로 들어가 잭으로 들어 올려 가져감. 출고는 반대.
- **향후 확장(셔틀이 리프트 탑승):** 바퀴 주행면이 통로 → P&D → 캐리지까지 이어져 있으므로 셔틀이 그대로 캐리지에 올라탈 수 있습니다. 캐리지 길이 1.4 m ≥ 셔틀 0.96 m. 추가로 필요한 것은 (1) 캐리지의 층 정렬 정밀도, (2) `ShuttleLock`(셔틀 고정), (3) 리프트 하중을 셔틀+파렛트 기준으로 설계, (4) 컨트롤러에서 리프트를 셔틀 이동 자원으로 예약하는 로직입니다. 모델에는 `ShuttleLock` 위치를 미리 넣어 두었습니다.

### 흐름
입고: 1층 입고 컨베이어 → 리프트 캐리지 → 목표 층 P&D → 셔틀이 저장 셀로 운반
출고: 셔틀이 셀에서 P&D로 운반 → 리프트 → 1층 출고 컨베이어

## 2. 기능 정의 (Unity 구현 기준, 초기값은 설정으로 변경 가능)

### 셔틀
| 상태 | 설명 | 기본값 |
|---|---|---|
| Idle | 대기 | |
| MoveAisle / MoveLane | 셀 단위 이동. 통로는 WheelsX, 레인은 WheelsY | 빈 차 1.5 m/s, 적재 1.0 m/s, 가감속 0.5 m/s² |
| SwitchWheels | 교차점에서만 가능 | 2.0 s |
| JackUp / JackDown | 파렛트 들기/내리기 | 각 2.5 s |

이동 규칙: 한 셀에는 셔틀 1대만. 적재 상태로 파렛트가 있는 셀에는 진입 불가. 방향 전환은 교차점에서만.

### 리프트
| 상태 | 설명 | 기본값 |
|---|---|---|
| Idle / MoveToLevel | 층 이동 | 1.0 m/s, 가감속 0.8 m/s² |
| ConveyIn / ConveyOut | 컨베이어 ↔ 캐리지 ↔ P&D 전달 | 0.5 m/s |
| Stop 동작 | `Stop_PX/NX` 올림/내림 | 0.5 s |

### 리프트 대수 자동 계산
```
리프트 1회 사이클(s) = 2 × (평균 수직 이동거리 / 속도 + 가감속 보정) + 2 × 전달 시간
리프트 1대 처리량(회/h) = 3600 / 사이클
필요 대수 = ceil( (시간당 입고 + 시간당 출고) / (1대 처리량 × 가동률 0.8) )
최소: 메인 통로당 1대
```

### 역할 분담 (강화학습 범위)
- **컨트롤러(WCS):** 입출고 지시 생성, 입고 저장 위치 결정(초기 규칙: 가장 가까운 빈 셀), 리프트 운전.
- **셔틀(강화학습 에이전트):** 받은 작업을 수행하기 위한 운반 능력. 이동 경로 선택, 잭 동작 타이밍, 다른 셔틀 회피와 양보, 교착 회피를 학습합니다.

## 4. 시뮬레이션에서 정한 운영 규칙 (2026-11-18 추가)
- **깊은 레인(LIFO):** 짐을 실은 셔틀은 파렛트 아래를 지날 수 없으므로 레인의 맨 앞 파렛트만 출고할 수 있고, 입고는 앞에서 닿을 수 있는 가장 깊은 빈 셀에 합니다. 레인당 진행 중인 작업은 1개입니다.
- **P&D:** 짐을 실은 셔틀은 자기 하차 목표인 P&D에만 들어갈 수 있고, 리프트는 짐 실은 셔틀이 P&D 위에 있으면 하역을 기다립니다.
- **복수 메인 통로:** 통로끼리 연결 통로가 없다고 보고, 셔틀을 통로별로 나눠 배치합니다 (층당 셔틀 수 ≥ 통로 수).
- **교착 판정:** 작업 중인 셔틀이 있는데 300초 동안 파렛트를 하나도 들거나 내리지 못하면 교착으로 보고 에피소드를 끝냅니다.
